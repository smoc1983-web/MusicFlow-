# MusicFlow Pro micro-patch — isolated Android proof of concept

**Test APK package:** `com.musicflow.patchtest`, entirely distinct from official MusicFlow `com.musicflow.preview`.

**Test procedure on Android:**
1. Download APK from GitHub Actions artifact `MusicFlow-Pro-Patch-DEMO-apk` in the workflow "Build isolated MusicFlow Pro micro-patch test".
2. Install the app next to existing MusicFlow (do not remove MusicFlow).
3. Verify "Скачать тестовый аудиотрек WAV" is disabled.
4. Tap "Имитировать оплату Pro" — *no payment takes place*.
5. Tap "Загрузить и проверить микро-патч". APK retrieves `activation.json` from a **different branch** `feature/musicflow-pro-demo-patch` and verifies an RSA SHA-256 signature embedded in test APK.
6. Tap "Скачать тестовый аудиотрек WAV". A self-created WAV is downloaded from the patch branch (base64 transport) and saved through Android MediaStore in `Music/MusicFlow Pro Test`.
7. Tap "Сбросить тестовую Pro-активацию"; confirm new downloads are blocked again. Previously saved WAV remains on disk.

**What this validates:**
- A *small, signed data patch* enables a preinstalled dormant feature without replacing the APK.
- The patch is fetched from an independent Git branch over HTTPS.
- The app validates the patch signature and rejects an invalid payload.
- The mock purchase gate works as UI logic; Android's normal MediaStore mechanism saves a downloaded WAV.

**What this does NOT validate or implement:**
- **No actual payment or subscription check**; mock purchase can be bypassed and is purposely not security-grade.
- **No code hot-swap or binary APK differential patch**. This is a signed config/entitlement-style patch.
- No copyrighted catalog track downloads, no monetization, no background subscription server or revocation.
- No main release, update, production signing or modification to the official app.
- Signature verification does not prove a specific user has purchased a subscription; production entitlements must come from a secure backend.

If this proof of concept passes on a real phone, the next stage is choosing a trusted billing backend and implementing time-limited server licenses. Only add downloading for music with appropriate rights.

Developer note: an intentionally one-time test signing key is generated by GitHub's debug build; the official MusicFlow release key is never used. The RSA private key used to prepare the test patch was not added to GitHub.
