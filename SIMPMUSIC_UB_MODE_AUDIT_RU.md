# MusicFlow 0.7.31 — исследование SimpMusic и применение ub-mode

## Изученные оригиналы
- https://github.com/maxrave-dev/SimpMusic — Kotlin Compose Multiplatform, Media3, GPL-3.0, недокументированные YouTube Music API.
- https://github.com/unclebob/ub-mode — MIT, `SKILL.md` (First Make it Work → Then Make it Right → Practice).

## Почему не переносился SimpMusic целиком
Различные архитектура, лицензия и музыкальный backend; монолитное объединение нарушило бы принцип минимальных проверяемых изменений. Код GPL-3.0 не копировался; YouTube Music scraper не был интегрирован и нельзя считать его документированным официальным API.

## Функции первой итерации (реализованы независимо)
1. SleepTimerPolicy: чистые правила времени; MusicFlowSleepTimerStore: одна дата завершения; PlaybackService: единственный исполнитель действия pause с сохранением очереди.
2. LyricsTiming: чистый расчёт позиции текста (бинарный поиск, ±5000 мс); интерфейс коррекции ±250 мс с сохранением в приложении.

## ub-mode — журнал проверок
- **Red TDD:** коммит тестов `2146d99769f54df08bd8f67dc1f33af212404c66`, ошибочный прогон https://github.com/smoc1983-web/MusicFlow-/actions/runs/44905189587 — отсутствовали `SleepTimerPolicy` и `LyricsTiming`, ожидаемая причина.
- **Fix:** реализованы минимальные функции и пользовательское подключение к Media3/Compose в отдельных последовательных коммитах.
- **Behavior tests:** `app/src/test/java/com/musicflow/app/SleepTimerPolicyTest.kt`, `LyricsTimingTest.kt`. Выполняются настоящим `:app:testDebugUnitTest`, а не только Python поиском подстрок.
- **Existing regressions:** Python/CI прежних версий (источники, ТВ, обновления и подпись).
- **Unsupported Kotlin gates:** оригинальные `unclebob/crapper`, `dryer`, `mutator` перечисляют Clojure, Java, Go, TypeScript, Rust и Python, но не Kotlin. Нельзя указывать CRAP/dryer/mutation оценки без подходящего Kotlin анализатора.
- **Policy:** фиксировать результаты CI и проблемы перед релизом; публиковать только с разрешения пользователя после проверки подписи APK.

## 0.7.32 — журнал продолжения (ub-mode)
1. Инспекция: Media3-журнал добавлял историю на переходе к записи до фактического звука; каждые 5 секунд сериализовал всю очередь.
2. **Red TDD**: тесты реального прослушивания, запрета накрутки перемоткой, радио и чистого агрегирования — коммит `4b28909db43fea6eb9ca9693d94295d4b29680bb`; GitHub Actions `44906693779` завершился ожидаемой ошибкой компиляции: отсутствуют `ListeningProgressTracker`, `ListeningStatisticsReducer`.
3. Реализация: чистый монотонный трекер (SystemClock.elapsedRealtime), метрики только во время `player.isPlaying`, игнорирование больших скачков позиции; история только после 3 с подтверждённого прослушивания.
4. Все показатели агрегируются и сохраняются **только на устройстве**, без внешних API и новых разрешений. Данные старой истории не конвертируются автоматически — их можно очистить отдельно.
5. Очередь сериализуется лишь при `onTimelineChanged`, прогресс по-прежнему сохраняется периодически.
6. Режимы повтора, перемешивания, резервные потоки и обновления остаются прежними. Проверки: Kotlin/JUnit + регрессионные скрипты + Android debug APK.
7. Инструменты crapper/dryer/mutator из официального ub-mode не заявляют поддержку Kotlin — не выдавать их метрики за результат Android-кода.

## 0.7.33 — продолжение: неизвестная длительность, сворачивание и фоновое аудио

**Причина:** Media3 ранее игнорировал позиции песен с нулевой метаданной длительностью; полноэкранный плеер не закрывался свайпом вниз; отдельной постоянной кнопки «Сейчас играет» не было.

1. **ub-mode / First Make it Work:** сначала добавлены Kotlin/JUnit-тесты `ResumePositionPolicyTest`, `PlayerMinimizePolicyTest` и `BackgroundPlaybackSoakModelTest`. Красный коммит `d9df45d6c0a07e3fed770c9f5b439674ae3c7d3c`; CI [44908244707](https://github.com/smoc1983-web/MusicFlow-/actions/runs/44908244707) ожидаемо остановился из-за отсутствующих двух классов.
2. **Then Make it Right:** реализована чистая политика восстановления с границами и исключением живого эфира; при неизвестной длине требуется флаг прошлой перемотки. Восстановление после рестарта сервиса откладывается до подготовленного seekable timeline; таймаут ожидания 20 секунд. Исправлена гонка: начальная позиция 0 не перезаписывает сохранённую позицию, пока не обработан отложенный запрос.
3. UI: стрелка вниз для закрытия полноэкранного плеера, свайп вниз на странице текущего воспроизведения; кнопка «Сейчас играет» в основном интерфейсе. Закрытие не вызывает `stop` / `clearMediaItems`.
4. Для фонового режима во время активного аудио добавлен `C.WAKE_MODE_NETWORK` и минимально необходимые `WAKE_LOCK` / `WAKE_WIFI_LOCK`.
5. **Испытания:** Kotlin/JUnit ускоренная 6-часовая модель — это проверка логики, **не** физическое воспроизведение. Отдельный GitHub Action [android-background-soak.yml](.github/workflows/android-background-soak.yml) запускает Android 35, 4-минутный локальный WAV, отправляет MusicFlow на домашний экран, гасит экран на 130 секунд и проверяет Media3 `isPlaying`, позицию и сохранение прогресса. Результат нужно проверять по CI.
6. **Ограничение:** фактическое воспроизведение через интернет, поведение аккумулятора и восстановление на физическом Samsung S24 автоматически этими тестами не подтверждаются. APK 0.7.33 не публиковался.
7. Оригинальные CRAP/Dryer/Mutator не поддерживают Kotlin; соответствующих числовых оценок не заявлять.
