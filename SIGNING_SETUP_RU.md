# Постоянная подпись и обновления MusicFlow

Выпуск **0.7.22** — первая версия с постоянным личным ключом подписи. Сборка **0.7.23** — тест обновления, подписанный тем же ключом и размещённый в GitHub Releases.

## Сохранить ключ

Загрузите предоставленные отдельно `musicflow-release.jks` и `signing-password.txt`. Сделайте минимум две защищённые резервные копии на разных носителях. **Никогда не коммитьте закрытый ключ или пароль в GitHub.** При утере ключа дальнейшее обновление приложения с тем же идентификатором становится невозможным без предусмотренного механизма смены ключей.

## Настроить дальнейшие GitHub Actions релизы

В Settings → Secrets and variables → Actions добавьте четыре секрета:

1. `MUSICFLOW_SIGNING_KEYSTORE_BASE64` — Base64 JKS-файла (одна строка).
2. `MUSICFLOW_SIGNING_STORE_PASSWORD` — пароль из `signing-password.txt`.
3. `MUSICFLOW_SIGNING_KEY_ALIAS` — `musicflow`.
4. `MUSICFLOW_SIGNING_KEY_PASSWORD` — тот же пароль.

Используйте существующий workflow `.github/workflows/publish-signed-apk.yml`, не заменяйте ключ при новых выпусках и не меняйте идентификатор пакета `com.musicflow.preview`.

## Проверить обновление

Перед удалением 0.7.20 сохраните скачанную музыку и настройки — удаление приложения обычно стирает его внутренние данные. Установите **0.7.22**, запустите MusicFlow с интернетом. Ожидается предложение **0.7.23** прямо в приложении, если обе версии опубликованы. Кнопка «Скачать и установить» скачивает APK и вызывает штатный установщик Android.

Для установки Android может попросить разрешение на установку из MusicFlow и подтверждение установки. Автоматическая скрытая установка APK не реализуется.
